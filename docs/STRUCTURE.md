## Where the brand lives

All of it is in `src/app/globals.css`. There is no `tailwind.config.ts`, and
that is not an omission. Tailwind v4 is CSS-first, so the theme is declared in
CSS with `@theme inline` rather than in a JavaScript config. The build brief
asked for `tailwind.config.ts`; v4 no longer generates or reads one for this
kind of configuration, and `components.json` records the Tailwind config path
as empty for the same reason.

Three layers sit in that file, in order.

**`@theme inline`** maps CSS variables to Tailwind utilities. shadcn's semantic
tokens come first, then the brand roles named exactly as the brand book names
them, so `bg-ground`, `text-ink-muted` and `text-steel` all work. Fonts and the
13px floor are declared here too: `--text-xs` is overridden to `0.8125rem` so
`text-xs` resolves to 13px instead of Tailwind's default 12px. That makes the
type floor structural rather than a rule somebody has to remember.

**`:root`** is paper, the light theme. **`.dark`** is graphite, the dark theme
and the brand's home ground. Both define the brand roles first, then point the
shadcn tokens at them, so a token change happens in one place.

`<html>` carries `dark` in `layout.tsx`, so the site opens on graphite and
matches the app splash screen. `themeColor` is `#191C20` for the same reason,
which keeps browser chrome from flashing a different colour on first paint.

Derived values are commented in the file. See `ASSUMPTIONS.md` for which ones
were interpolated rather than quoted.

## The colour rule, in code

The money is the only colour. Chrome and content are greyscale, and steel is
reserved for the credit figure.

In practice that means the shadcn tokens are all greyscale, including
`--primary` and `--ring`, and steel only ever arrives through three component
classes in `globals.css`:

- `.money` for a cost or a balance, mono, tabular, steel
- `.money-held` for credit held against an answer in flight, mono, tabular, gold
- `.figure` for figures that are not money, mono, tabular, current colour

If a new component needs steel and it is not showing money, that is the signal
to stop and check the brand book rather than to add a token.

## Section composition rules

One section per file in `src/components/sections`, kebab-case, exporting a
single named component in PascalCase. Barrel exports live in `index.ts`.

Sections are server components by default. Reach for `"use client"` only when a
section genuinely needs interactivity, and keep the client boundary as small as
the interactive part.

Sections own their content, never their outer spacing. `SectionShell` decides
padding, max width, the eyebrow and the heading, so vertical rhythm is set once
and cannot drift section by section. A section that needs to break the shell
should say why in a comment.

Unfinished sections use `SectionPlaceholder` and state plainly what is missing.
An unfinished page should never read as a shipped one.

Every figure that is money uses `formatRand` from `src/lib/format.ts` and one
of the mono classes. Never hand-write a rand amount in JSX, because the
en-ZA form is R2 495,00 and getting the space and the comma right by hand
across a codebase does not hold.

Headings use Archivo automatically through the base layer, so `h1` to `h4` need
no font class.

## Content management approach

No CMS. Content lives in `src/content` as typed TypeScript modules, exported
`as const` so copy is type-checked at build time and a renamed field breaks the
build rather than the page.

`site.ts` is the single source of truth for site-wide copy, bundles, values,
differentiators, competitor pricing and navigation. Every claim in it
is traceable to the brand book, and anything the brand book does not state is
absent rather than invented. Comments in the file record where a figure came
from and when it was checked, which matters most for competitor pricing.

When a section needs more than a paragraph or two, give it its own module in
`src/content` rather than growing `site.ts` past the point of scanning.

If editorial ownership ever moves to someone who does not open a code editor,
that is the moment to revisit this decision. Until then, typed modules keep
copy in version control and in review, which is worth more than a dashboard.

## Conventions

Files are kebab-case, everywhere, including components. Components are
PascalCase in code. Imports use the `@/*` alias, never deep relative paths.
TypeScript is strict. `src/components/ui` is generated by shadcn, so prefer
re-adding a primitive over hand-editing one, and comment any edit that has to
stay.
